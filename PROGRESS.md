## A real bug caught and fixed this chunk

Alembic's autogenerate emitted `postgresql.JSONB(astext_type=Text())` in the
migration file without importing bare `Text` — a known Alembic quirk, not a
BGC-scape design issue, but it would have silently broken the *very first*
`alembic upgrade` anyone ran. Caught by actually executing the migration in
this sandbox rather than trusting the generated file; fixed by adding
`from sqlalchemy import Text` to `migrations/versions/d2256596c9d0_initial_schema.py`.
Flagging this explicitly because it's exactly the kind of thing that's easy
to miss if migrations are generated but never applied.

## Key design decisions made this chunk (fuller rationale in ARCHITECTURE.md)

1. **Provenance is structural, not conventional** — `source_id` +
   `evidence_level` are non-nullable on every scientific entity, enforced
   by the schema, not by convention.
2. **`native_enum=False` everywhere** — enums are `VARCHAR` + `CHECK`, so
   adding a new BGC class or taxonomic rank is a normal column-level
   migration, not a Postgres `ALTER TYPE` operation.
3. **Dual-dialect types** — `sqlalchemy.Uuid` and a custom `JSONVariant`
   (JSON everywhere, `JSONB` specifically on Postgres) so the same model
   code runs against in-memory SQLite in tests and real Postgres in
   production with zero branching.
4. **`BGC.bgc_class` is single-valued for MVP** — hybrid/multi-class
   regions are handled via the `HYBRID` enum value + free-text `subtype` +
   full-fidelity `raw_annotation` JSON, not a many-to-many table yet.
5. **`PhylogeneticTree` supports inline OR object-storage Newick**,
   enforced by a `CHECK` constraint requiring at least one.
6. **Pydantic schemas are read-only in this chunk.** Write/input schemas
   are deferred to Phase 1b, where their shape should be driven by the
   actual source formats (MIBiG JSON, GTDB TSV, antiSMASH region JSON)
   rather than guessed at now.

## Known constraints from this build environment

- **This sandbox cannot reach mibig.secondarymetabolites.org,
  gtdb.ecogenomic.org, or NCBI directly** — its network allow-list covers
  package registries (PyPI, npm, crates) and GitHub, not general research
  data sites. `docs/DATA_SOURCES.md` was written using `web_search`/`web_fetch`
  (which *do* have broader reach) rather than `bash_tool`. Phase 1b
  ingestion code can plausibly be written and fixture-tested here (via
  `web_fetch`-retrieved small examples saved as test fixtures), but
  **cannot be run end-to-end against the live databases from inside this
  environment** — that step needs to happen where you run this for real, or
  you can paste back results/errors for me to debug from.
- The GitHub Actions CI workflow is a strong, standard-pattern first draft
  but has not been executed by an actual runner (no CI access from here).
  Validate on the first real push.
- Test suite runs against in-memory SQLite. Alembic upgrade/downgrade were
  verified against real (file-based) SQLite in this chunk; **not yet
  verified against real Postgres** — `docker-compose.yml` is provided for
  exactly that check, next time you're somewhere with Docker access.
